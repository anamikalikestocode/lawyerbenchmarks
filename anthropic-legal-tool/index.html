lawyer benchmarks

oct 28, 2026

I tricked Anthropic’s new legal tool and it failed 52% of my contract traps.

Anthropic launched a tool for contract lawyers today. You give it your playbook (i.e. rules and guidance) and a contract, and it marks each clause:

  • Standard (fine)
  • Fallback (acceptable)
  • Deviation (breaks a rule)

I tested it on a classic negotiation trick: the other side gives you what you asked for BUT takes away a protection in the same edit (usually it's a word or two).

I took 27 contracts (public SEC filings), wrote a playbook for my client in each, and slipped 50 redlines with this trick into the other side’s drafts. Since each change goes against my playbook, the right answer should have been “Deviation”. However, I found that:

  • The tool passed 26 of the 50 traps as Standard.
  • ... While a simple prompt on Opus only mistakenly passed 1.
  • Haiku, the smallest Claude model, with a simple prompt also only passed 3.

So the fix is probably in the grading instructions or generally how the tool is set up.

Here are 4 examples:

1. The deposit

My client keeps a deposit with the platform, which can take fines out of it. The edit added the official letter my client asked for before any deduction and deleted "reasonable". So the fines no longer have to be reasonable.

The tool noted it as standard even though its note even said the clause "does not say deductions are limited to reasonable amounts"

Key: red is deleted, green is added, yellow is unchanged (same for all pictures). The tool only saw the final text.

2. The adviser

My client is an adviser who does the work the Board reasonably requests. Before, any officer could ask. The edit made it Board only, as asked, and dropped "reasonably".

The tool noted it as standard even though twice the note said the clause "does not say requests must be reasonable".

3. The bad batch

My client (Intersect) buys an ingredient from Hovione and can reject a batch that's off spec, with a lab settling any dispute. Two sentences work as a pair:

  • The first decides who wins the dispute. The edit deleted "materially" so the batch now has to meet spec exactly. Good for my client.
  • The second, starting at "Hovione shall pay all the fees", decides who pays for the lab. The edit left "materially" in. Bad for my client.

Say the spec is 99.5% pure and the batch is 99.4%: my client wins the dispute but still pays for the lab and the replacement.

4. The licence

My client (NLS) gets a cut of Eurofarma's sales, so it wants a say in Eurofarma's sales plan. The edit added the duty to hit the plan's numbers, as asked. But now Eurofarma only needs my client's OK to sell fewer units, launch later or spend less. Any other change is its call alone. (The tool flagged a different clause under the same rule, just not this one.)

What gets through

In the 50, a plain missing word usually got caught. Two other tricks got through most:

  • Belief swap: 13 of 18 passed. The trigger moves from what happened to what the other side believes happened, so they get to decide.
  • Half-fix: 10 of 17 passed. Two sentences work as a pair and the edit fixes only one.

The other tricks (a missing word, narrowed approval, a protection moved into another section) got through 3 times in 15.

What its notes show

  • It grades the clause as a whole: Once it sees what you asked for, the missing thing is discarded as a side note: "matching the standard … although".
  • It shortens your rule when it explains itself: "only Board-requested services" instead of "the services that the Board of Directors reasonably requests". A clause can match the short version and still break the real one.
  • It notices the difference but still says standard.

What fixes it

Opus with the contract, playbook and a simple prompt caught 49/50 traps (even Haiku is more or less as good), so the model can do this. The problem is that the tool's setup makes every model worse.

When you rebuild the tool’s setup from its code and run the same models through it, they begin missing traps too. So the fix belongs in the tool’s setup: how it prompts the model and how it’s configured.

For example, a line in its prompt says a clause is Standard when it “meets our standard position in substance”. But a clause can be substantively correct AND also minus one legally significant word, and it would still pass that test.

Limitations

Full disclosure, I’ve been researching exactly this for a bit: AI contract edits that look like a win but actually give something away. The first few edits came from real AI redlines I had already flagged as bad.

When this tool launched, it was the perfect test for the type of redline I had already flagged: would a tool built to check contracts catch them?

So I had Claude build 50 more just like them, on real contracts, each one fitting that kind of trap (please don't read 52% or 26/50 as an error rate!)

I kept the explanation to each example to a few lines so this stays short but there’s plenty more reasoning behind every call. If you’d read one differently, my DMs are open!
